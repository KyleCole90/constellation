# A write whose answer was lost is found again, never sent twice

A request to Canvas can land while its response is lost. Before it writes again, the app reads the LMS and looks for its own earlier write. Each provider read below exists so that this search works.

- `observe` in `src/main/providers/canvas-term.ts` reads a `not_found` item as `deleted`, and `#observeSet` in `src/shared/providers/fake-canvas/server.ts` does the same. A delete whose response was lost then settles as done on retry. Don't turn `not_found` into an error there.
- `observe` for announcements in `src/main/providers/canvas.ts` lists every topic, delayed ones too, unlike `announcements`, which drops posts that aren't shown yet. A post this app made still reads as landed, so it is never posted twice.
- `apply` in `src/main/providers/canvas.ts` sends fields in `WRITE_ORDER`. Once one fails or its answer is lost, it sends nothing more and marks the rest failed, so a comment never lands on top of a grade that didn't.
- `RemoteState.targetVersion` in `src/shared/domain/change.ts` must change when the target itself moved: a new attempt, the student writing again, or the course changing. `classify` turns a moved `targetVersion` into a `target-changed` conflict instead of writing over new work. `CourseContent.version` in `src/shared/domain/content.ts` moves when anything in the course moves, because it is the `targetVersion` of a publish draft and of text fixes.
- For a `message` change, `RemoteState.messages` in `src/shared/domain/change.ts` lists the conversations with that student whose subject equals `MessageContent.subject`, the assignment title. That match is how `classify` sees an earlier send of the same message.
- `copySignature` in `src/shared/domain/change.ts` names a course-copy job by its source only, because Canvas doesn't echo a migration's date shift back. `src/main/providers/canvas-term.ts` builds job signatures with the same function, and `MigrationRecord.signature` in `src/shared/providers/fake-canvas/migrations.ts` equals the same text. `seen` keeps an earlier job with the same source from passing as this one.
- `withKeptEntries` in `src/shared/domain/change.ts` adds the ids of the entries now in the LMS to `seen` when the teacher chooses "Post mine anyway". Those entries aren't this change's write. Without this, every later send flags them again as a possible own write.
- The fake Canvas server in `src/shared/providers/fake-canvas/server.ts` applies a write inside `call`, before it decides whether to lose the response. A lost response still leaves the field applied, as on a real LMS, and the recovery is tested against that.
